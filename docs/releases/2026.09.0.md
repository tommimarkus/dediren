## Compatibility

**Generated layout output now uses `layout-result.schema.v3`.** Each edge's `points` field is replaced by one typed `route`: either a polyline with points or a cubic Bezier path with a start and control-point segments. Consumers of generated layout JSON must migrate and regenerate stored layouts. There is no v2 output fallback. Authored source models, layout requests and render policies remain compatible.

## Routing and output fixes

- Native ELK owns ordinary ports, cycle breaking and hierarchical ordering. Self-loops, weighted cycles, compact returns and visual-band spacing are protected.
- Cubic geometry survives the full pipeline: native SVG curves and bounded approximation for waypoint exports.
- Labels attach to actual route segments; unsatisfied placement is diagnosed. Line jumps, masks and visible bounds use consistent geometry.
- Quality checks detect node proximity, accidental overlaps and distinct crossing events. draw.io preserves separate attachment points; ASCII preserves intermediate turns.
- Paint verification uses the pinned Playwright 1.62.0 runtime with an unchanged calibration gate. Dependency and GitHub Actions updates since the preceding release are included.

All 21 layout fixtures pass zero-crossing checks, and all 13 campaign views retain zero crossings. The complex self-module view improves from 26 to 18 crossings; the remaining native-engine limitation is explicitly documented, not claimed globally unavoidable. See the [routing acceptance report](https://github.com/tommimarkus/dediren/blob/v2026.09.0/docs/features/routing-acceptance.md) for geometry measurements, Firefox and draw.io evidence, and verification limits.
